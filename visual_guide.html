Part 2 — GBFS Node

gbfs_node(
  Pos, % pos(Row, Col)
  RevPath, % path, newest first
  Steps % step counter
)
Open list entry — sorted by heuristic H:
h(H, gbfs_node(pos(3,3), [...], 4))
The open list is kept sorted ascending by H — smallest H = most promising = popped first.
Why store the path reversed? In Prolog, prepending to a list ([NewPos|RevPath]) is O(1) — much faster than appending to the end. At the goal, we call reverse/2 once to get the forward path.
Open List vs Closed List — What they do:
📋

Open List

Nodes waiting to be explored. BFS uses a FIFO queue. GBFS uses a min-heap sorted by heuristic H.

✅

Closed List

Positions already visited. Before adding a neighbor, we check it's not in the closed list to prevent cycles.

🔄

The Loop

Pop from open → goal check → expand neighbors → add valid ones to open → repeat.

🔵 Part 1 — Breadth-First Search Uninformed
BFS expands all nodes at depth d before any node at depth d+1. This guarantees finding the nearest survivor (fewest steps).
Key insight: BFS uses a FIFO queue — children are appended to the tail, so the oldest (shallowest) node is always processed first. The first survivor we pop from the queue is necessarily the closest one.

    🟢 Part 2 — Greedy Best-First Search Informed
    GBFS uses a heuristic to always expand the most promising node first. Goal: collect as many survivors as possible.
    Heuristic H = Manhattan distance to the nearest remaining survivor.
    Manhattan distance between pos(R1,C1) and pos(R2,C2) = |R1−R2| + |C1−C2|
    Lower H = closer to a survivor = higher priority in the open list.
    H-Value Map (both survivors remaining)

    Each cell shows H = min(Manhattan to s1, Manhattan to s2).
    Smaller = robot is closer to a survivor.

    How GBFS uses H
    1️⃣
    Generate all valid neighbors of the current node.
    2️⃣
    Compute H for each neighbor. Insert into the open list in sorted order (ascending H).
    3️⃣
    Always pop the node with lowest H from the open list — that's the greedy choice.
    4️⃣
    When a survivor is reached, start a new trip from that position (keeping the closed list).

      ⚖️ Algorithm Comparison
      How do BFS and GBFS differ in strategy, guarantees, and results?
      Property 🔵 BFS (Part 1) 🟢 Greedy BFS (Part 2)
      Algorithm typeUninformedInformed
      Open list structureFIFO Queue — append to tailSorted List / Min-Heap by H
      Next node to expandOldest (shallowest) nodeNode with lowest heuristic H
      Uses heuristic?No — blind searchYes — Manhattan distance to nearest survivor
      GuaranteeOptimal — always finds nearest survivor (fewest steps)Greedy — fast but not guaranteed optimal
      GoalReach the single nearest survivorCollect as many survivors as possible
      Battery trackingYes — stops if battery hits 0No explicit battery (Steps tracked instead)
      Multi-trip?No — single trip, stops at first survivorYes — iterates: find survivor → collect → repeat
      Result on this grid5 steps, 50% battery, pos(3,4)8 steps total, 2 survivors collected
      CompletenessComplete (finds answer if path exists)May miss a survivor if path is blocked by visited cells
      Prolog key predicatebfs_loop/6gbfs_loop/7 + collect_all/8
      Why does BFS expand so many nodes? It doesn't know which direction leads to a survivor, so it fans out in all directions equally — 17 pops before finding pos(3,4). Guaranteed shortest path but expensive.
      Why is GBFS faster? The heuristic guides the robot toward survivors. From pos(2,0), GBFS immediately heads toward pos(3,4) (H=5) instead of exploring random directions. It finds survivors in fewer expansions — but may not find the globally optimal sequence.
